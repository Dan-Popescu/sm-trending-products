# Implementation coverage and release gates

This record maps the approved fifteen-ticket delivery plan to actual software and behavioral tests as of 2026-10-22. It describes what exists, what the scenarios exercise, and what still requires external acceptance. The presence of a test is not an execution result; consult the verification report and test output for the final run. Local PGlite/Moto execution must not be reported as native PostgreSQL or production S3 verification.

## Verified engineering gates

[Native CI evidence](../verification/native-ci.md) records the successful run,
exact tested revision, artifact digest, and executed boundaries.

1. **Native PostgreSQL:** 142 tests passed with no skips, including eight-backend
   shared credential contention, exclusive collection claims, parallel forward
   claims, and reviewed identity transfers.
2. **Deployment image:** Compose validation and the checked-in Dockerfile build
   passed on the GitHub-hosted Linux runner.
3. **Isolated restore:** the real backup and restore scripts restored application
   and Dagster databases plus four copied objects into fresh containers. Logical
   products, identity, alerts, and frozen-decision fingerprints matched.
4. **Publication:** PR #1, global PRD #2, specification issues #3–#8, and delivery
   issues #9–#23 are published. See [publication](publication.md) for original
   local commit mapping and the PR's actual merge state.

## Release gates that remain open

1. **Production storage and VPS:** supply the target machine and secrets, validate
   provider semantics/permissions and private access, and measure headroom. Neither
   a production VPS nor a production S3 account has been deployed by this work.
2. **Representative scale and faults:** measure realistic history, skew, workers,
   source latency, retention, cache states, and compaction on target hardware.
   Exercise process termination across publication boundaries and recovery under
   sustained load. Functional concurrency tests are not a universal capacity or
   fault-tolerance certificate. Apply actual provider prices to measured units.
3. **Live TikTok capabilities:** verify app/account scopes, allowed purpose,
   response meanings, coverage, quotas, retention/deletion, and revocation. T15
   remains pending until the required credentials and permissions exist.

## Acceptance interpretation

The software covers all six functional areas. Native functional concurrency,
image construction, and isolated recovery have now been executed successfully;
production infrastructure, representative capacity/fault exercises, real source
permissions, and actual market outcomes remain separate. Preserve those boundaries
when closing acceptance tickets or presenting business results.
