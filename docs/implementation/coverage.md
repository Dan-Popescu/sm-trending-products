# Implementation coverage and release gates

This record maps the approved fifteen-ticket delivery plan to actual software and behavioral tests as of 2026-10-22. It describes what exists, what the scenarios exercise, and what still requires external acceptance. The presence of a test is not an execution result; consult the verification report and test output for the final run. Local PGlite/Moto execution must not be reported as native PostgreSQL or production S3 verification.

## Release gates that remain open

1. **Native PostgreSQL:** run the suite against the supported native service. The [contention tests](../../tests/test_native_concurrency.py) use eight independent native backends for shared credential limits and collection claims; evaluation integration also covers concurrent outcome claims. These explicitly skip under PGlite. Genuine locking/fencing races and interruption around cross-store writes still need native execution; PGlite cannot certify these properties.
2. **Deployment image:** build the checked-in Dockerfile and validate the Compose deployment on a Docker-capable host. The [CI workflow](../../.github/workflows/ci.yml) contains native PostgreSQL tests, Compose validation, and image build steps, but a checked-in workflow is not evidence that its remote run succeeded.
3. **Isolated restore:** the [CI recovery exercise](../../scripts/ci-recovery.sh) seeds controlled evidence, captures a complete database/object backup, invokes fresh native PostgreSQL and object-store containers, and compares logical evidence fingerprints after restore. It must actually run successfully. Confirm committed observations, identity history, frozen alerts/decisions, and task recovery; record duration and data size. Local static validation does not close this gate.
4. **Production storage and VPS:** validate the actual provider's semantics/permissions, supply the target machine and secrets, verify private operator access, and measure resource headroom. Neither the VPS nor a production S3 account has been deployed by this implementation.
5. **Representative scale:** run the workload on the target hardware with realistic history, skew, multiple workers, source latency, retention, cache states, and compaction. Apply explicitly sourced provider prices to measured units; do not extrapolate unlimited capacity from the small local sample.
6. **Live TikTok capabilities:** verify the actual app/account scopes, allowed purpose, response meanings, market coverage, quotas, retention/deletion rules, and revocation behavior. T15 remains pending until those prerequisites exist.
7. **Remote publication:** resolved on 2026-10-22. [PR #1](https://github.com/Dan-Popescu/sm-trending-products/pull/1), global PRD #2, six specification issues, and fifteen delivery issues are published. See [publication](publication.md). CI execution status is recorded separately from source publication; no production deployment is claimed.

## Acceptance interpretation

The software covers all six functional areas and supplies the interfaces needed to perform the remaining checks. That does not make every original acceptance requirement complete: native concurrency, full restore, image/VPS rollout, production capacity, and live-source permissions require execution environments or inputs that were not available. Preserve this distinction when closing tickets, publishing a PR, or preparing the final handoff.
