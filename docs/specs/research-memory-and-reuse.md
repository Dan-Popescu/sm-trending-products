## Goal and delivery

Implement all four independently verified research improvements without changing
what evidence means. Isolate parallel work, review each immutable slice on Standards
and Spec axes, run complete final PR CI, and merge autonomously as slices qualify.
No deployment, external source/platform connection, paid provider call, commerce
activation, permanent report cache or data deletion is authorized by this spec.
Preserve capture schema 40, hourly cadence, persisted formats, public report bytes
and identities for admitted inputs, current policy/ownership/withdrawal checks,
knowledge-time semantics, real/synthetic separation and existing ranking behavior.

## M1 — Research metadata admission (#183)

Research history readers must bound selected source-object count and encoded
metadata bytes before transferring full descriptors or fetching payloads. Cover
TrendInsights and CompetitionInsights and therefore their composed brief, change
and progression callers. Generalize existing SQL selection/admission and
WindowMetadataBudget machinery; EvidenceWindows.prepare also computes rankings
and is not a replacement for research semantics. Existing configured object/byte
budgets remain authoritative. Count objects within a dataset, not datasets only.
Preserve temporal predicates including conservative legacy bounds, ordering,
namespace/retention protection and coherent selection during concurrent changes.
Oversized required metadata raises a typed explicit refusal before any payload
traffic; do not return a truncated or partially complete report. Count and byte
limits do not claim an exact RSS bound or eliminate database statement timeouts.
Test one dataset, multiple datasets/aggregate bytes, oversized descriptor, exact
admission boundaries, no-payload refusal, complete normal bytes/IDs and retirement.

## S1 — Lean final transcript eligibility (#184)

Provide one bounded eligibility-only page sharing the authoritative transcript
checks and original row/cursor rules. ContentProgression final validation uses
only transcript identities and pagination; it must not query analysis state.
Keep its final text/metric retention fence and all current source/policy/ownership,
cutoff and provenance checks. Existing analysis-aware selection remains unchanged.
Check completed/running/uncertain/reused analysis states, unavailable rows, paging,
whole report identity and concurrent withdrawal. The measured baseline eight-text
combined case has 882 driver executes, including 16 irrelevant analysis queries;
these figures include controls, not database server CPU.

## S2 — Set-based eligibility (#187; depends on S1)

Batch initial page and final metadata checks behind the same authoritative
transcript interface. Preserve per-row namespace, committed dataset, availability,
cutoff-specific resolved unique owner/confidence, entity/source match, current
policy verification/retention clock, delivery, provenance and denial reasons.
Retain immediate authoritative individual refresh before hydration: ownership and
policy are mutable independently of retirement. Keep analysis-aware historical
barriers and source-specific completed-analysis validation. Do not cache eligibility
proofs across calls. Bounded set-based SQL must not create a global source scan,
unbounded dependency walk, pool deadlock or hidden loss of row-level refusals.
Verify policy, ownership, source and publication changes with native PostgreSQL,
whole payload/ID parity and multiple page-size SQL measurements.

## C1 — Operation-local pure classification reuse (#185)

Within DecisionChanges.compare, reuse pure classification and script fingerprint
results across its two briefs only after each pass has independently hydrated
eligible text. Exact text identity, language, full taxonomy identity and method
belong to the key. Context, attribution and source authority remain fresh per pass.
Do not silently share the separately requested progression operation or introduce
a process-global cache. Bound retained entries and bytes; decline reuse on pressure
without dropping evidence. Mutable returned reports must not mutate memoized state.
Release all operation-local state on success or failure. Preserve exact report
bytes/IDs, quote offsets, Unicode, unsupported languages, full-tail fingerprints
after the mention cap, taxonomy/text/language changes and historical cutoffs.
Measure actual whole comparison CPU on alternating matched long-text runs and
ordinary inputs; report noise and memory tradeoffs rather than inventing savings.

## A1 — Neutral bounded input and final display (#186)

Move genuinely shared bounded JSON-object decoding out of CLI adapters into a
small neutral module; dashboards must not depend on CLI internals for this duty.
Preserve byte limits, strict decoding/object-shape behavior, public parser aliases
where compatibility requires them and adapter-specific model validation/errors.
Use existing display_safety for selected repeated research wrappers, with current
runtime secrets and final JSON serialization. Interpret raw typed structure before
sanitizing final display values. Keep persisted collector redaction and default
machine JSON outputs distinct; do not alter executable plans or action IDs.
No generic dashboard framework or speculative configuration abstraction.
Test byte/shape/encoding limits, default outputs, final serialization/credential
collisions and failure clearing without removing existing source guards.

## Evidence and verification

Native PostgreSQL tests serialize with /tmp/night-native-tests.lock. Preserve all
required CI, acquisition handover, backup/restore and current schema checks.
Independent reviewers verify scope and maintainability separately. Synthetic local
measurements establish software behavior and scoped work, not live profitability,
whole-VPS continuous CPU/RAM, throughput capacity or monthly cloud savings.
